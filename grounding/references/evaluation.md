# Grounding pilot evaluation

Evaluate at least four completed real tasks:

- an installed JavaScript or TypeScript package;
- a package from another ecosystem;
- an installed CLI or live platform;
- a technical concept or architecture decision.

For each task, record the skill revision, evidence key, target class, evidence summaries, reused evidence, specialist agents, outcome, technical corrections, and avoidable research or reporting overhead.

Score each check with `pass`, `fail`, or `not applicable`:

| Check | Pass condition |
|---|---|
| Target | One bounded target, question, and environment are named. |
| Authority | The result uses the governing project source and highest-authority primary source available. |
| Current reality | Version, exact source, configuration, or deployed state is verified when applicable. |
| Synthesis | Project-specific synthesis is labeled and supported by a current same-boundary precedent when one is needed. |
| Timing | Substantive recommendations have supporting evidence; uncertain API combinations are checked before being presented as working solutions. |
| Reuse | Unchanged evidence is reused; only invalidated claims are rechecked. |
| Focus | Research and reporting resolve a specific decision; any delegation adds independent value. |

Preserve the existing invocation policy. Treat technical corrections as evidence for the relevant check, and report gaps without claiming that these cases prove general correctness. Change the skill only where observed behavior supports the change.
